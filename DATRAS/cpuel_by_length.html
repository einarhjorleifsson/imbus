CPUEL: emulation and validation

Reconstructing CPUEL row-by-row from raw HH/HL; discrepancy anatomy across all 17 Survey-Quarters

Author

Einar Hjörleifsson

Published

June 1, 2026

Modified

July 1, 2026

This document asks: can we reconstruct CPUEL row-by-row from raw HH and HL tables? compute_cpue_emulation() does this and is validated here across all 17 Survey-Quarter combinations and all available years. The goal is to understand what CPUEL computes internally and to attribute row-count and CPUE discrepancies to their specific causes.

1 Emulating CPUEL from raw HH/HL

compute_cpue_emulation.R reconstructs the ICES CPUEL row structure from raw HH and HL tables. It is primarily a forensic tool — for understanding what CPUEL does internally and for diagnosing discrepancies.

1.1 Function overview

Parameter Default Purpose
haul_key "short" "short" matches CPUEL’s output key (Survey:Year:Quarter:Platform:Gear:HaulNumber); "full" uses unambiguous .id
collapse_sex TRUE FALSE retains sex from HL — used for EVHOE in this validation (CPUEL retains F/M/U for EVHOE; all other surveys have sex = NA)
filter_species_validity "1" Codes contributing to non-zero CPUE values; does NOT affect the zero-fill species pool

The zero-fill species pool is always built from all HL records in valid hauls for the Survey-Quarter-Year, regardless of SpeciesValidity code — matching CPUEL behaviour. Only CPUE values (non-zero rows) are filtered to SpeciesValidity == "1".

Very large row diff — both causes combined: BITS Q2 (127 % total: 116 % catch + 11 % ZF — vintage effect on sparse early-years data), SCOWCGFS Q4 (96 % total: 66 % catch + 30 % ZF — 2019 CPUEL held only 3 aphias, a preliminary submission).

1.2.2 Temporal patterns

Row differences have two independent causes with opposite implications:

  • Catch row diff (catch_diff_pct): driven by HL data changes since the CPUEL snapshot. A large catch diff means real abundance estimates have shifted.
  • Zero-fill row diff (zf_diff_pct): driven by differences in the zero-fill species pool and methodology. Zero-fill rows have n_hour = 0 and do not enter CPUE estimates.

1.2.2.1 Total row diff and its catch / zero-fill decomposition

1.2.2.2 CPUE diff vs catch row diff

CPUE diff and catch row diff should track each other: both reflect genuine changes in the HL data. When they diverge, it signals subsampling or CPUE calculation differences beyond simple row counts.

Key contrasts:

  • EVHOE Q4: mean total row diff 37 %, mean catch diff ~3 %, mean CPUE diff ~3 %. The large row diff is entirely in the zero-fill component. EVHOE’s CPUEL is stored in two independent batches per year (see anatomy section below): a main species batch and a supplemental Atlantic mackerel batch. The April 2016 computation (years 2005–2015) included no zero-fill rows at all; the August 2018 and later computations do. The emulation always generates full zero-fill, producing 70–90 % row diff for the 2005–2015 years but near-zero catch diff throughout.
  • SWC-IBTS Q4: both catch diff and CPUE diff ≈ 40 % — HL data has genuinely changed since the 2018 CPUEL snapshot.
  • NS-IBTS Q4, ROCKALL, SCOROC: all three components < 1 % — near-perfect.

1.2.2.3 Species (aphia) count difference over time

1.2.2.4 BITS: the sign flip

BITS Q1 and Q4 show the clearest temporal pattern. Before ~2008 the emulation overshoots CPUEL: early CPUEL snapshots were computed on sparser HL data. After ~2010 the emulation undershoots: BITS expanded to multi-vessel operations and short-key collapsing dominates. CPUE differences remain small throughout.

1.2.2.5 EVHOE Q4: two-batch CPUEL structure and its effect on zero-fill

EVHOE Q4 CPUEL is stored as two independent computation batches per year, each with its own DateofCalculation:

  1. Main species batch — the bulk of the data. The computation date determines whether zero-fill was applied:
    • April 2016 vintage (years 2005–2015, 2016): zero zero-fill rows.
    • August 2018 vintage (years 1997–2004, 2017): full zero-fill included.
    • 2019+ vintage (2018 onward): full zero-fill included.
  2. Supplemental Atlantic mackerel batch (DateofCalculation = 20181205, all years): aphia 127023 (Scomber scombrus) computed separately with proper zero-fill, adding 50–84 zero-fill rows per year.

1.3 Known discrepancy causes

1.3.1 Cause 1 — Short-key haul collapsing (emulation < CPUEL)

Multi-vessel surveys assign HaulNumbers 1–n independently per vessel; two physically distinct hauls can share the same (Platform, Gear, HaulNumber) key. The emulation’s distinct() collapses them, producing fewer zero-fill rows than CPUEL, which computes internally at the full .id level before truncating the key.

NS-IBTS Q1 2018: short-key collapsing example
Metric Value
Total valid hauls (.id) 364
Distinct (Platform, Gear, HaulNumber) 313
Hauls collapsed by short key 51

Effect: ~5–15 % row undercounting for affected Survey-Years. Use haul_key = "full" to avoid this at the cost of CPUEL output-format compatibility.

1.3.2 Cause 2 — CPUEL data vintage (emulation > CPUEL)

Each CPUEL record carries DateofCalculation. When that date precedes the current HH/HL data, the local HL contains species not present in the CPUEL snapshot, producing more emulation rows.

1.3.3 Cause 3 — Presence-only species (fixed in current version)

Species recorded with SpeciesValidity ≠ "1" and NumberAtLength = NA (presence-only notes) had previously been excluded from the zero-fill pool via filter(NumberAtLength != 0) before the species list was built. Fix: build the pool from ALL HL records for valid hauls before that filter.
